# Deep Company Analysis — Investment Checklist DOCX Report V101

## Purpose

V101 adds an evidence-rich `.docx` export over the completed Michael Shearn Appendix C checklist. It is a presentation/export layer only. The report does not become a new question, evidence, financial, valuation, or investment-decision SSOT.

## Source lock

The generator imports `CHECKLIST_ITEMS`, `SECTION_ORDER`, `SECTION_TITLES`, and `SOURCE_LOCK` directly from `modules.deep_company_analysis.appendix_c`. It therefore renders Q01–Q59 in the source-locked order and exact wording already owned by Appendix C; V101 does not maintain a second hard-coded copy of the 59 questions.

The report accepts answer/evidence state keyed by existing Qxx references. Unknown IDs are rejected. Missing answer state is rendered as `Unknown` rather than inferred.

### Q33–Q52 evidence guard

For Q33–Q52, a supplied status is not enough to imply research completion. When usable evidence is absent, V101 deterministically renders the question status as `Unknown`. This preserves the analyst/evidence boundary for management and growth research and prevents the export layer from manufacturing a conclusion.

## Read-only report sections

1. Cover and research boundary statement.
2. `What changed since last review` supplied by the analyst/workspace.
3. `Critical unknowns` supplied by the analyst/workspace.
4. Q01–Q59 grouped into the ten Appendix C printed sections, with exact source wording, status, evidence, source references, and analyst note.
5. Financial evidence snapshot supplied by the canonical financial owner.
6. Cyclical normalization context supplied by V100 / its owning context layer.
7. Financial provenance/source table, preferring the columns `source_field`, `source_module`, `source_period`, `data_origin`.

V101 intentionally does not yet add the complete 10Y + TTM financial/chart book. That is the next reporting phase so the DOCX export contract can be regression-tested before the larger quantitative presentation layer is added.

## Architecture boundaries

- Trecapital Data Layer remains financial SSOT.
- Appendix C / owner chapters remain question/evidence SSOT; V101 renders references only.
- V100 remains the owner of cyclical-normalization calculations; V101 only renders supplied rows.
- Valuation and MOS remain owned by Module 2. V101 performs no valuation calculation and creates no second valuation engine.
- AI role remains `Research Assistant`.
- The analyst owns interpretation and conclusions.
- No weighted management, growth, or checklist score is created.
- No BUY/HOLD/SELL recommendation is generated.
- No automatic intrinsic-value/MOS or Investment Research Gate change is generated.

## Determinism and formatting

`python-docx==1.1.2` was already pinned in the repository before V101. The generated file fixes DOCX core created/modified metadata to a stable timestamp for reproducible test structure. Deterministic tests inspect the actual OOXML package and source-locked wording rather than treating a successful `Document.save()` call as sufficient evidence.

The report uses compact professional tables suitable for analyst review. Numerical formatting remains the responsibility of the canonical supplying module; V101 does not recalculate or reinterpret financial values. The planned 10Y + TTM presentation phase will apply the existing Trecapital display contract (VND bn 0 decimals, percentages/multiples 1 decimal, negative red/positive green) at the dedicated financial report layer.

## API

```python
from modules.deep_company_analysis.investment_checklist_report import (
    build_investment_checklist_report_docx,
    write_investment_checklist_report_docx,
)
```

`build_investment_checklist_report_docx(...)` returns DOCX bytes. `write_investment_checklist_report_docx(path, ...)` writes those bytes without modifying any owning state.

## QA / acceptance

Dedicated deterministic coverage validates:

- source lock remains valid and exactly 59 questions are rendered;
- Q01–Q59 order and exact wording equal Appendix C references;
- unknown/non-source question IDs are rejected;
- Q33–Q52 remain `Unknown` without evidence;
- generated bytes form a valid DOCX ZIP/OOXML package;
- evidence/source/analyst note and provenance columns are present;
- Research Assistant / Analyst ownership is explicit;
- no duplicate SSOT, valuation, scoring, BUY/HOLD/SELL, or automatic Research Gate behavior is introduced.
